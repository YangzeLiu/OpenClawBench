# Annotation Pipeline

Code that turns raw agent runs into labeled trajectories. Labels were produced in two passes: a 4-stage pipeline with a DeepSeek-V4-Pro judge over the full corpus, followed by a single-judge re-labeling pass with the 5-class v3 prompt, whose output is the `v2_*` label fields in the released `data/train.jsonl` and `data/test.jsonl`. The human-verified labels in `data/human_verified.jsonl` were produced by human annotators and are not generated by this code.

## Files

| File | Role |
|---|---|
| `build_oracle_fusion_dataset.py` | Fuse event-enriched trajectories with the benchmark oracle results (pass/fail per task) |
| `build_risk_slices.py` | Heuristic trajectory risk scores and step-level onset candidates |
| `build_llm_annotation_inputs.py` | Build `annotation_input_packets.jsonl` (one packet per trajectory) for the LLM judge |
| `run_fulltax_pipeline.py` | Orchestrator: sharding, quality tiers, per-model output tables, merge |
| `run_fulltax_pipeline_core.py` | Stage A/B1/B2/C judge calls and validation |
| `relabel_single_judge.py` | Single-call re-labeler with `prompts/relabel_prompt_v3_5class.md` |
| `prompts/` | Stage prompts of the 4-stage pipeline and the v3 5-class re-labeling prompt |
| `taxonomy/` | Full 8-subtype candidate taxonomy, closed label set, quality-tier definitions |

## The 4-stage pipeline

Stage A (triage) reads the trajectory, routes it as anomalous or normal and proposes candidate subtypes. Stage B1 picks one subtype from the closed label set for anomalous routes. Stage B2 fills the structured fields (onset steps, severity, recoverability, evidence segments). Stage C verifies consistency and flags records for review. Each record is then assigned a quality tier (`taxonomy/fulltax_quality_tiers_definition_v1.md`).

The pipeline works over the full 8-subtype candidate taxonomy. Three of those subtypes (`state_contamination`, `parallel_coordination_breakdown`, `ambiguity_mishandling`) received no instances, so the re-labeling prompt and the released labels use the remaining five.

## 5-class taxonomy (v3)

| Label | Meaning |
|---|---|
| `write_under_unresolved_ambiguity` | Agent commits (external write or confident reply) while user-spec ambiguity is unresolved |
| `premature_external_write` | External write before sufficient grounding |
| `weak_evidence_commitment` | Commitment under partial or noisy evidence without acknowledging its weakness |
| `capability_gap_overcommitment` | Tool returned an explicit denial or no data, and the agent committed anyway |
| `error_ignored_escalation` | Explicit error in a prior step, followed by a higher-risk action that does not address it |
| NORMAL (null) | No commitment under an information deficit |

Decision rules, discriminators between subtypes and worked examples are in `prompts/relabel_prompt_v3_5class.md`.

## Re-labeling released or new trajectories

Input rows need `source_model`, `trajectory_id`, `num_steps` and `steps[...]` (each step with `step_id`, `event_type`, `thinking`, `action_text`, `reflection_text`), which is the format of the released splits.

```bash
export DEEPSEEK_API_KEY=...
python annotation_pipeline/relabel_single_judge.py \
    --in  hf_data/data/train.jsonl \
    --out results/relabel_v2.jsonl \
    --workers 64
```

The re-labeler is resumable: re-running the same command retries only failed records. `detector/scripts/build_v2_split.py` turns its output into a stratified train/test split.

## Running the 4-stage pipeline on new runs

The preprocessing scripts take `--data-root` pointing at the raw outputs of one batch of agent runs (event-enriched trajectories plus the benchmark `results.jsonl`) and write derived folders under it. The pipeline then expects packets at `<RAW_ROOT>/BFCL/<source_model>/<input_subdir>/annotation_input_packets.jsonl`.

```bash
export DEEPSEEK_API_KEY=...

python annotation_pipeline/run_fulltax_pipeline.py \
    --mode run --dataset BFCL --source-model <source_model> \
    --data-root <RAW_ROOT> --output-root <RAW_ROOT>/annotation_results \
    --workers 16 --resume

# After all shards finish, merge per-model outputs
python annotation_pipeline/run_fulltax_pipeline.py \
    --mode merge --dataset BFCL \
    --data-root <RAW_ROOT> --output-root <RAW_ROOT>/annotation_results
```

Per-model outputs (`master_table_all.jsonl`, `accepted_main_all.jsonl`, `accepted_repaired_all.jsonl`, `review_or_unresolved_all.jsonl`, `dataset_summary_all.json`) are written to `<RAW_ROOT>/annotation_results/BFCL/silver_labels/<source_model>/`.
